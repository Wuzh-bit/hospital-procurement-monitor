# 医院采购线索监测 Skill

面向中国大陆公开采购信息的 AI Agent skill：定期跟踪目标医院的需求调查、市场调研、参数征集、采购意向及后续采购公告，将线索沉淀到本地 Excel/SQLite 台账。

**当前版本：v1.0**（发布版）

## 适用范围

- 目标医院、项目关键词和信息源均由使用者确认；不含预置客户数据。
- 仅访问无需登录的公开信息源，不绕过验证码、登录、付费墙或反爬机制。
- 优先适配腾讯 WorkBuddy，也兼容可读取 GitHub skill 目录并运行 Python 的其他 Agent。
- 支持聊天文本、CSV/XLSX 与 DOCX 医院名单；扫描件 OCR 不在首版范围。

## 安装与开始使用

将本仓库链接提供给支持 GitHub skill 安装的 Agent，或复制整个目录到其 skill 目录，随后说：

> 帮我建立医院采购线索监测任务。

Agent 会先收集周期、医院名单、至少一个项目关键词、通知邮箱和信息源建议，并在任何定时运行或邮件发送前请您确认。

## 工作方式

```text
确认医院与来源 → Python 合规采集 → 规则初筛/去重 → AI 审阅候选
→ SQLite 台账与 Excel 报告 → AI 判为相关的新增线索通知
```

Python 处理重复、日期、链接和关键词等确定性工作；AI 仅审阅候选公告并判断相关性，控制 Token 消耗。首次建立时的信息源“发现 + 实测”也由脚本 `scripts/discover_sources.py` 完成（零 Token），AI 只负责每家医院至多 1 次搜索官网主页、以及把脚本输出的评估表转给用户批量确认。批量新增医院时无需手动整理官网地址：配置高德 Key 可运行 `scripts/lookup_homepages.py` 用 POI 批量自动补官网（零 AI 搜索），没有 Key 则由 AI 逐家单次搜索补齐。详细流程见 [SKILL.md](SKILL.md)。

## v0.3 更新要点（轻量化与防死循环）

针对真实试运行中“信息源发现与实测验证”耗时过长、消耗大量 Token 甚至陷入推理死循环的问题：

- 信息源从“三类”（官网/代理机构/省平台）收敛为“两类”：**官网公告栏目 + 所在省/市政府采购或公共资源交易平台**；删除代理机构来源的自动发现。
- 新增 `scripts/discover_sources.py`：用 Python 直接抓医院官网主页找“公告/招标/采购”栏目、实测所有候选 URL（可达性/列表形态/标题日期/分页线索），并依据预置表 `references/gov-platforms.json` 实测省平台；**对政采/公共资源平台做公告栏目下钻**（抓平台首页找“采购公告/交易信息”等静态栏目页），并轻量探测站点自带的 GET 搜索表单；AI 不再做逐页搜索与逐页实测。
- 新增 `scripts/lookup_homepages.py`（可选加速）：配置高德 Web 服务 Key 后，按医院全名用 POI 搜索批量查询官网地址，零 AI 搜索；批量新增几十家医院时一键补齐 `homepage`。
- 新增来源级关键词定向采集（`keyword_filter` + `keyword_early_stop_pages`）：公告量巨大的政采/公共资源平台只保留标题命中关键词的公告，连续 N 页零命中即停止翻页，减少抓取范围。
- **JS 平台浏览器无头渲染**（`sources[].mode: "js"`）：对公开、无需登录的 JS 列表页（中国政府采购网、部分省级平台）用浏览器无头渲染后采集。**已集成 Playwright（可选依赖，优先）** + 系统浏览器 dump-dom 兜底，验证可解锁 ccgp 国家级政采公告及北京/河南/江苏/海南等省平台；`discover_sources.py` 可用 `--js-probe` 开启渲染探测。Safari 不支持命令行渲染。
- **可用性报告异常优先**：只报“所有信息源都不可用”的全挂医院明细，其余医院一行带过，回复“全部确认”即批量启用；官网与属地公共资源平台同时可用时默认双启用、双抓取（交叉验证），审阅时跨来源同标题公告自动合并为一条并注明。
- 全网搜索刹车：WebSearch 一律“单次查询、必有结论”；首次建立每家医院至多 1 次搜索（官网由 POI 或用户提供则 0 次），总预算 ≤ 医院数 + 3；失败一律标“人工关注”，禁止追加/递归搜索。
- 首次试运行轻量化：`--since` 默认近 7 天回看窗口，减少首轮数据量。
- 保留全部既有能力：两级审阅、压缩摘要、去重台账、pagination、批量确认、通知与清理。

## v0.2 更新要点

基于真实数据回测：采集器支持来源级分页（`pagination`，可随 `--since` 提前停止）；导航噪声自动过滤；线索按 canonical URL 去重，AI 判不相关/未标注的候选持久化到 `skipped_notices` 表避免重复送审；RSS/Atom 日期、GBK 编码、英文词边界匹配、xlsx 导出等健壮性修复；支持对已入库线索做状态更新。另含 TLS/证书问题的中文诊断。

## 本地数据与依赖

真实配置、缓存、数据库和报告保存在 skill 目录外的用户数据目录（如 `monitor-data/`），请勿提交至 GitHub。脚本的 JSON、CSV、SQLite、HTML/RSS 采集仅依赖 Python 标准库；需要 `.xlsx` 时执行 `pip install -r requirements.txt`，否则仍生成 UTF-8 CSV。

## 测试

核心辅助函数带有冒烟测试（标准库 `unittest`，无第三方依赖）：

```bash
python -m unittest discover -s tests -v
```

覆盖 URL 公网校验（SSRF 防护）、canonical 去重、notice_id 稳定性、中英文日期解析、关键词词边界匹配、栏目噪声过滤与编码探测。

## WorkBuddy 使用建议

先手动完整执行一次并确认报告附件正常，再在自动化中选择本 skill、设置周期和工作目录。自动化提示词只允许读取已确认的配置和来源，不允许在无人值守状态下新增医院、修改关键词、启用新来源或改变收件人。
