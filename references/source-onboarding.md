# 信息源准入

每个来源先展示给用户确认，再启用长期监测。**每家医院信息源固定两类：官网公告栏目 + 所在省/市政府采购或公共资源交易平台**；不再自动发现“医院常合作代理机构”来源（历史已确认的 `agency` 类型来源仍可继续采集，类型保留兼容）。

## 整理流程（三步，一次性/低频）

1. **收集官网地址（尽量零搜索）**：优先请用户直接提供医院官网主页或公告直达页地址，填入医院清单 `homepage` 字段；未提供时 AI 对每家医院至多 1 次搜索：`"{正式名称}" 官网`，取前 5 条结果中最权威的域名。搜不到或存疑就留空标“官网未知”，不再追加搜索。
2. **脚本实测（Python，零 Token）**：运行 `scripts/discover_sources.py`（输入结构见 `templates/hospitals-input.example.json`）：
   - 抓官网主页、下钻 1 层找“公告/通知/招标/采购/公示/信息公开”栏目链接（每家 ≤3 个）；
   - 按预置表 `references/gov-platforms.json` 实测所在省/市政府采购与公共资源交易平台：**先抓平台首页并下钻 1 层找“采购公告/交易信息/结果公告”等静态栏目页**（政采平台新版多为 JS 门户，老式平台常有静态栏目列表），栏目连同首页一起实测；同时轻量探测站点自带的 GET 搜索表单（`?keyword=xx`），在评估输出中标出；
   - 对每个候选输出实测结果（可达性、静态可解析、列表条目数、标题日期、分页线索样本），写入 `work/source-assessment-<时间戳>.json`。
   - 脚本不搜索、不翻全站、不推理；每家的请求数 ≤ 9。**JS 检索页/需登录的平台照旧标“人工关注”，不逆向接口、不模拟浏览器。**
3. **AI 读表 + 用户批量确认**：AI 只读评估 JSON，整理成可用性评估表一次性列出（每家官网候选 ≤3 条 + 省平台候选 ≤4 条含下钻栏目，逐条一行摘要）；用户回复“全部确认”即启用所有标“可用”的来源；“人工关注”的不启用但明确告知，个别调整由用户单独指出。**同一医院多个同名栏目（如多个“通知公告”）只保留主栏目；公告量巨大的政采/公共资源平台来源，启用时一并确认关键词定向（keyword_filter）。**

只有**实测可用且用户确认**的来源写入配置 `sources`。信息源整理只在首次建立与中途调整时进行（一次性/低频）；每次运行直接使用配置，零搜索。

## 每个来源需要确认的信息

1. 来源名称、类型、对应医院和公开入口 URL。
2. 该页面是否无需登录、无验证码，且允许正常浏览。
3. 可覆盖的公告类型与大致更新频率。
4. 采集方式：RSS/Atom 优先；静态 HTML 列表次之；无法稳定读取则标注“人工关注”。多页静态列表应为单一来源配置 `pagination`（见配置字段），不要把每一页注册成独立来源。
5. 是否存在重复来源、域名迁移、访问频率限制或明显的页面结构风险。

## 代理机构来源（不再自动发现）

不做基于名称相似或单次搜索的代理机构推断。若用户明确要求启用某个已确认的代理机构来源，按“每个来源需要确认的信息”逐项确认后以 `agency` 类型写入配置；历史已确认的 agency 来源不受影响，仍按常规流程采集。

## 失败处理

出现登录、验证码、403/429、DNS 失败、页面改版或无法解析时，记录来源 ID、时间和错误摘要；继续处理其他来源。连续失败的来源不应提高请求频率、不做 AI 重试搜索。提示用户改为 RSS、确认新公告入口，或保留为人工关注。

采集 manifest 中的 `warnings` 是来源健康度信号：`未解析到任何条目` 通常意味着页面是 JS 动态渲染、需要登录或 URL 失效；`疑似导航页/JS 列表` 意味着选错了栏目入口。省级政府采购/公共资源交易平台常见只有 JS 检索页，采集器读不到；遇到这类来源应改为医院官网静态列表、等价静态入口，或标注“人工关注”，不要通过逆向接口、模拟浏览器等方式绕过。
